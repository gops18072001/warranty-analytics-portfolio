# 04 — Excel Warranty Analysis

`Warranty_Analysis.xlsx` — a working analyst workbook built on the same warranty
data as project 01.

## Why this exists

A lot of warranty reporting still happens in Excel, and a workbook that other
people have to maintain is a different artefact from a one-off analysis. This is
the same data as project 01, built the way it would be handed to a team.

## The one thing worth noticing

**Only `Batch_Data` contains hard numbers.** It is the SQL extract — one row per
production batch, 4,584 rows, claims rolled up. Every figure on every other
sheet is a live formula pointing at it:

```
=SUMIF(Batch_Data!$E$2:$E$4585, $A5, Batch_Data!$J$2:$J$4585)
```

Click any cell and the derivation is visible. Refresh the extract and the whole
workbook re-computes. Nothing is pasted, which is the difference between a
workbook someone can maintain and a screenshot with numbers in it.

## Sheets

| Sheet | What it does | Excel used |
|---|---|---|
| `README` | Provenance, sheet guide, the right-censoring caveat | — |
| `Batch_Data` | SQL extract, 4,584 batches, filterable, frozen header | AutoFilter, freeze panes |
| `Supplier_Scorecard` | Claim rate and cost per unit by supplier, variance vs fleet average, status flag | `SUMIF`, `IFERROR`, nested `IF`, colour-scale and cell-rule conditional formatting, bar chart |
| `Monthly_Trend` | Claim rate by production month, 3-month moving average | `SUMIF`, `AVERAGE` over a rolling window, line chart |
| `Pareto_Cost_Drivers` | Top 20 component/defect pairs by cost | running `SUM` for cumulative %, bar chart |

## What it shows

One supplier, Shreeji Connectors, runs a **4.80% claim rate against a 1.82%
fleet average** and accounts for **52% of warranty cost on 20% of the volume**.
The scorecard flags it automatically — the status column compares each supplier
to the fleet average rather than to a hardcoded threshold, so the flag still
works when the data is refreshed.

## Reading the trend honestly

The last few months on `Monthly_Trend` look better than they are. A batch
produced recently has had weeks to fail, not years, so its claim rate is
understated. This is right-censoring, and it is the easiest way to accidentally
report an improvement that is not happening. Compare batches only once they
have had comparable time in the field.

## Data

Synthetic, generated by `../01_sql_warranty_analytics/generate_data.py` with a
fixed seed, with known issues planted so the analysis can be checked against
ground truth. **Not real manufacturer data.**

